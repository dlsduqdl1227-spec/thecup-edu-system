# 더컵에듀 시스템

## 2026-11-19 날짜 중심 일정·개강 통합

- 관리자 **상담 · 수업 관리 → 일정·개강**에서 월간 달력의 날짜를 누르면 해당 날짜의 시간표·예약·FLOW 목록만 표시합니다. 날짜 선택은 다른 운영 메뉴를 다녀와도 유지되며, 긴 목록은 페이지로 나눕니다.
- 시간표 행을 눌러 상세 확인, 수동 마감·다시 열기와 예약 승인을 처리합니다. 기존 확정 예약과 자동 휴무는 임의로 차단하지 않습니다. **일정 추가**에서 추가 시간 일괄 생성·날짜 복사·스테이션 설정을 엽니다.
- 같은 화면의 **개강 관리** 또는 접힌 **이달의 개강 모집**에서 모집 과정·인원·공개 설정을 수정합니다. 기존 과정은 월 단위 자료이며 모집 시작일을 실제 수업 날짜로 바꾸어 표시하지 않습니다.
- **상담·수강**에서 상담 접수와 과정 등록, **예약 승인**에서 월별 대기 건을 관리합니다. 회원 계정·현장 결제·피드백·운영 설정은 **추가 관리**에 모았습니다. 상담/예약 알림은 해당 메뉴로 바로 연결됩니다.
- 공개·수강생 화면의 외부 일정 표시는 **마감**, 같은 날 남은 회차가 있으면 **일부 마감**입니다. 실제 FLOW 제목·장소는 관리자에게만 표시합니다. 상담 버튼은 링크 색상 충돌을 해결하고 흰 글자의 둥근 버튼으로 정리했습니다.
- 검수: `qa/admin-schedule-check.mjs`는 격리된 메모리 DB에서 Chromium/WebKit의 날짜/월/키보드 이동, 예약 확정, 마감·해제, 개강 수정, 상담 알림 이동, 320–1440px 및 버튼 대비를 확인합니다. 운영 DB에 테스트 회원·과정을 추가하지 않습니다.

## 자동 시간표 · 월간커피 FLOW 연동

- 이번 달부터 3개월의 평일 예약 시간을 자동 생성합니다. 수업 시간은 09:00–11:30 / 12:30–15:00 / 15:30–18:00이며, 점심 11:30–12:30·주말·공휴일은 예약할 수 없습니다. 기존 시간표·확정 예약·수동 차단 기록은 변경하지 않습니다.
- FLOW의 **더컵 미디어센터 프로젝트** 또는 **장소가 더컵미디어센터인 일정/회의**는 별도 체크 없이 저장된 `[시작, 종료)`와 겹치는 회차만 차단합니다. 종일 일정만 해당 날짜 전체를 차단합니다. ‘종료 미정’ 표시가 있어도 저장된 시작·종료 값을 사용하고, 실제 종료 값이 없을 때는 관리자에게 입력을 요청합니다. 날짜·시간·장소 변경·삭제·상위 프로젝트 삭제를 반영하며, 센터 외 일정은 수동 차단 설정이 있을 때만 포함합니다.
- FLOW 저장 후 인증된 서버 간 갱신 요청을 전송합니다. 예약 신청·확정 직전에는 원본을 다시 조회하며, 실패하면 신청/확정을 잠시 막습니다. 마지막 정상 차단은 유지합니다. 5분 주기 복구와 화면 조회 시 30초 간격 재확인도 적용합니다.
- 관리자 **상담 · 수업 관리**에서 마지막 연동 시각, 차단 날짜, 기존 예약과의 충돌을 확인하고 **지금 동기화**로 재시도합니다. 확정 예약은 자동 취소하지 않습니다.
- EDU Worker `FLOW_CALENDAR_SECRET`와 FLOW Pages `EDU_CALENDAR_SECRET`는 같은 32자 이상 서버 비밀값입니다. 클라이언트·Git·로그에 저장하지 않습니다. `BOOKING_AUTOMATION_ENABLED=true`가 자동 생성을 활성화합니다.
- 공휴일은 KASI 달력자료 및 [우주항공청 2027년 월력요항](https://www.kasa.go.kr/prog/plcyBrf/brief/kor/sub01_01_04/view.do?plcyBrfNo=431)에 근거한 2026~2027년 자료입니다. 임시공휴일 발표 시 보완하며, 확인되지 않은 연도는 자동 개방하지 않습니다.
- 로컬 두 앱 연동 검수: FLOW `node qa/serve-calendar.mjs`, EDU `vite --config qa/vite-calendar.config.mjs --port 5174`, 이후 `node qa/calendar-check.mjs`. 두 QA 서버는 운영 계정·DB가 아닌 메모리 DB만 사용합니다.

더컵에듀의 교육 상담, 수강 등록, 예약, 재고, 수업별 사용량, 영수증, 월별 매출과 교육자료를 한곳에서 관리하는 운영 웹앱입니다.

## 2026-10-29 교육 중심 개편

- 첫 화면은 과정 안내 → 교육비·권장 회차 → 디플로마·레벨 통합 → 기업교육 → 상담 폼 순서입니다. Pretendard와 화이트·블랙·그레이를 사용합니다.
- 일반 모듈 회당 2.5시간, 구독자 8만원·비구독자 12만원. Foundation 3회·Intermediate 6회·Professional 10회는 **센터 권장 수업 계획**이며 SCA 공식 평가·선수 요건과 별개입니다. 디플로마 구성 교육비는 약 20% 할인, 시험비 별도. Q Grader는 6인 모집과 개강 일정 확인이 필요하며 회차·금액을 관리자가 직접 확인합니다.
- 홈페이지 상담 폼은 이름·연락처·연령대·유입 경로·복수 관심 과정·연락 방법을 접수합니다. 자동 문자/카톡 전송은 하지 않습니다. 담당자가 전화·문자 링크 또는 카카오톡 상담으로 직접 연락합니다.
- 관리자 **상담 · 수업 관리 → 상담·수강 등록**에서 신청자를 검색·선택하고 상담 기록/담당 강사를 지정합니다. **결제 확인 · 수강 과정 등록**으로 과정·레벨·총 회차·담당 강사·수업 시간·결제 확인 금액을 등록하면 회원도 승인됩니다. 패키지는 실제 구성 과목별로 나누어 등록합니다.
- 수강생은 **내 수업 예약**에서 과정과 시간을 선택합니다. 장비는 바리스타/물=에스프레소, 로스팅=로스팅, 브루잉/센서리/그린커피/지속가능성/Q=브루잉으로 배정합니다. 기존 시간표를 그대로 사용하며 자동 생성·삭제하지 않습니다.
- 담당 강사는 직원 로그인 후 **상담 · 수업 관리 → 수업 승인·완료**에서 배정된 수업만 확정·거절·완료 처리합니다. 관리자도 대리 처리할 수 있습니다. 강사·학생·장비의 겹치는 확정 시간을 차단합니다. 서로 다른 장비/강사는 동시 수업 가능합니다.
- 신청 대기·확정·완료·노쇼는 회차에 포함하고, 취소·거절은 복구합니다. D1의 단일 SQL 트리거로 동시 신청의 회차 초과를 막습니다. 중지한 과정은 새 신청·추가 확정을 막지만 이미 확정된 일정은 유지합니다.
- 기존 수강생(이 기능 적용 전 DB에 존재한 회원)은 기존 예약 권한을 유지합니다. **신규 회원**은 결제 확인된 과정이 있어야 예약할 수 있습니다. 기존 예약 이력과 로그인·보안코드를 바꾸지 않습니다.
- 새 과정은 수강 관리용 결제 확인 기록이며 매출 장부에 자동 합산하지 않습니다. 기존 현장결제 목록에서는 선결제 과정 예약을 제외하고, API도 중복 현장결제를 차단합니다. 교육자료 과목·레벨 권한은 자동 부여하지 않습니다.

### 데이터와 보안

- DB 준비 작업의 진행 중 Promise는 요청 사이에 공유하지 않습니다. 완전히 끝난 초기화 상태만 재사용하므로 최초 요청 중단이 다음 로그인 요청을 막지 않습니다. 동시에 시작한 요청의 기존 열 추가는 실제 스키마를 다시 확인하며, 요청 컨텍스트 오류는 내부 영문 대신 재시도 가능한 한국어 503 응답으로 처리합니다. 로그인·보안코드·권한 정책은 그대로입니다.
- `lib/learning-schema.ts`가 기존 테이블에 `reservations.enrollment_id`만 추가하고 상담·수강 테이블 및 예약 검증 트리거를 생성합니다. 기존 회원·예약·매출 행을 덮어쓰거나 일괄 변경하지 않습니다. 새 회원용 `learning_members` 표식은 INSERT 트리거로만 생성됩니다.
- 전체 연락처는 새 상담 테이블에서 AES-GCM으로 암호화합니다. 관리자와 배정된 강사만 인증된 상세 API에서 확인할 수 있고 목록·공개 API에는 반환하지 않습니다. 회원 로그인용 전화 해시는 그대로 유지합니다.
- 암호화 키는 `SESSION_SECRET`에서 용도 분리해 파생합니다. 이 키를 교체할 때는 기존 상담 연락처의 재암호화 절차가 먼저 필요합니다. 예전 해시/끝자리만 있던 회원의 전체 번호는 복원하지 않습니다.
- 동의문 버전·동의 시각을 기록합니다. 종료(`CLOSED`)된 새 상담은 종료 후 1년이 지나면 다음 인증된 상담 조회 때 삭제합니다. 회원·예약·결제 기록은 이 정리에 포함하지 않습니다. 카카오톡 자동 알림, SMS 발송 서비스, 외부 결제 연동은 포함하지 않습니다.
- `/api/learning/consultations`는 동의·입력 검증, 동일 출처 검사, 전화/IP 단위 제한을 적용합니다. `/api/learning/admin`은 관리자 또는 시간강사 전용이며 전체 연락처 응답은 캐시하지 않습니다.

## 2026-10-23 화면 정리

- 모바일·태블릿(1024px 이하)은 아이콘과 큰 터치 영역의 하단 메뉴를 사용합니다. 관리자 주요 메뉴 4개와 `전체 메뉴`, 수강생 홈·스케줄·내 예약·실습 기록·교육자료를 표시합니다.
- 로스팅 프로파일·매뉴얼 화면과 관련 API, 생두 전환 입출고 API는 종료했습니다. SCA 로스팅 교육·로스팅 스테이션 예약은 유지합니다.
- 프레젠테이션의 `가로 보기`는 기기 회전 잠금·전체화면 거부·방향 전환 API 미지원 상태에서도 내부 화면을 회전합니다. 휴대폰을 옆으로 잡으면 가로로 읽을 수 있으며 `자동 방향`으로 원래 동작으로 돌아옵니다. 실제 기기의 회전 잠금 설정은 변경하지 않습니다.
- 생두·기타 품목과 과거 프로파일 DB는 삭제하지 않습니다. 현재 재고 및 입력에서는 제외하며, 재고 Excel의 과거 장부에는 기존 기록을 보존합니다. 기존 수량·매출·회원·예약·교육 권한은 이 배포로 변경하지 않습니다.

## 핵심 기능

- 이름 + 등록된 휴대폰 번호 + 보안코드 로그인 (운영자용·수강생용 구분)
- 관리자 / 정규직원 / 시간강사(남부) 구분과 직원별 메뉴 권한
- 원두(일반·구스토)와 우유만 재고 관리합니다. 원두는 kg으로 입력·표시하고 기존 g 단위 데이터도 자동 환산합니다
- 입출고·실사에서 0 입력은 확인 후 실사 잔량 0 처리. 기본 현황에서는 제외하고 소진 품목에서 재입고하며 기존 기록은 보관합니다. 품목 검색·상태 필터·품목별 바로 입력·반영 전후 수량 미리보기를 제공합니다.
- 목록에 없는 품목을 LOT·가공 방식·소비기한·입고 수량과 함께 직접 등록
- 기존 더컵인벤토리 `entries` 기록을 품목·LOT별 현재 잔량과 재고 장부로 자동 연결
- 시간강사(남부)의 수업별 우유·원두 사용량 기록
- 우유 영수증 이미지 최적화 보관 및 구매 비용 자동 반영
- 2022–2026년 CSV 매출·순익 이관, 연도별 1–12월 상세 탭 및 월/분기/연도 그래프
- 매출·지출 장부와 월별 순익 실시간 합산, CSV 기준 금액과 추가 등록 내역 구분
- 상담 승인 회원용 커피 스테이션 예약 포털과 월별 캘린더, 관리자 승인형 예약 운영
- 관리자 월간 달력에서 여러 날짜·시간대·스테이션을 선택하는 예약 일정 일괄 생성
- 관리자 설정의 카카오톡 채널 링크로 공개 상담 버튼 즉시 연결
- 관리자와 공개 캘린더 30초 자동 동기화, 가장 가까운 운영 월 자동 선택
- 운영자·수강생·수업 예정자 진입 분리, 예정자용 공개 빈자리 조회와 수강생 ID 로그인
- 에스프레소·브루잉·로스팅 스테이션 예약, 현장결제와 실습 기록·피드백 관리 (수강생 승인 후 별도 이용권 발급 불필요)

## SCA 교육자료

- 위치: 관리자 `운영 관리 → SCA 교육자료`, 승인 수강생 `내 수강 화면 → 교육자료`
- 자료: `lib/sca-edu/decks/` — 커피 입문, 바리스타·브루잉·생두·로스팅·센서리, 물과 예방정비 Foundation, 지속가능성 Foundation의 8개 과목·18개 자료. JSON은 서버 코드에 번들하며 `public/`에 두지 않습니다. 신규 자료는 수업용 재구성본이며 공식 시험이나 AST 전체 교재를 대체하지 않습니다.
- 권한: 관리자는 검토 중 자료까지 전체, 발표자 노트, PPTX 다운로드. 예약 승인만으로는 교육자료가 열리지 않습니다. 관리자가 개인별로 선택한 과목만 승인 수강생이 웹에서 열람하며 노트·출처 메모는 서버에서 제거됩니다. 정규직원·시간강사 계정만으로는 열람할 수 없습니다.
- 공개 절차: 수강생 체크 → 과목·레벨 체크 → `선택 레벨 일괄 승인` 또는 `선택 레벨 일괄 해제` → 대상 확인. 체크는 이번 작업의 대상을 뜻하며 현재 열람권한은 `권한 보기`에서 확인합니다. 페이지 간 선택은 유지되고 검색·상태 변경/새로고침은 수강생 선택을 초기화합니다. 한 번에 최대 100명, 선택하지 않은 수강생·레벨과 예약 이용 승인은 유지됩니다. `PUT /api/edu/members/bulk`는 검증·권한 변경·감사 기록을 하나의 D1 트랜잭션으로 처리하며 잘못된 대상이 하나라도 있으면 부분 저장하지 않습니다. 저장 즉시 적용되며 재배포가 필요 없습니다. 원본의 review 상태는 유지하고 초안·준비 중인 자료는 열리지 않습니다.
- 개인별 권한은 `edu_member_levels`에 저장합니다. 0018 마이그레이션은 기존 `edu_member_courses`의 유효한 권한만 기존 16개 자료의 해당 레벨들로 이관합니다. 신규 2과목이나 일반 예약 회원에게 권한을 추가하지 않습니다. 레거시 테이블은 보존하되 판정에 사용하지 않으며 구 API는 409로 차단합니다. 승인 회수·삭제 시 해당 수강생의 레벨 권한을 지우고 재승인 후 다시 설정합니다.
- `수강생 승인하러 가기` 버튼은 운영 · 개강 관리의 상담·회원 탭으로 연결됩니다.
- 기존 운영 DB에는 0016~0018이 적용돼 있습니다. 교육자료 내용·워터마크·공유 미리보기 수정에는 추가 마이그레이션이 필요 없습니다. 트리거는 회원 삭제/승인 회수 시 그 회원의 교육자료 권한만 제거합니다. 기존 회원·예약·매출 기록을 변경하지 않습니다.
- 차트 보강: 기존 19개 차트에 사례용 4개를 추가한 23개 편집 가능한 차트. `required-visuals.json`은 센서리 모든 레벨에 플레이버 휠, 브루잉 모든 레벨에 SCA Brewing/Water Chart 원본을 삽입합니다. 물과 예방정비에도 Water Chart가 포함됩니다. 가상 데이터는 실제 측정값과 구분합니다.
- 원본 이미지: 사용자가 보유한 강사 자료를 전체 페이지로 렌더링합니다. 이미지·원본 PDF·생성 SQL은 Git이나 `public/`에 넣지 않습니다. D1 `edu_assets`에서 `/api/edu/decks/:course/:level/assets/:asset`로만 제공하며 해당 레벨 권한을 매 요청 검사합니다. 관리자 PPTX에 원본 이미지를 삽입하고, 이미지 호출이 실패하면 불완전한 PPTX 다운로드를 중단합니다.
- 배포 순서: 기존 DB의 0017 적용 여부 확인 → **0018 SQL만** 적용 → `node scripts/prepare-edu-assets.mjs outputs/sca-assets`로 생성한 비공개 SQL을 검토·적용 → 이미지 길이/해시 확인 → 코드 배포. 과거 마이그레이션을 운영 DB에 일괄 재실행하지 않습니다. 원본 PNG 파일명은 `flavor-wheel-ko`, `sca-brewing-2019`, `sca-water`입니다. `qa/sqlite-env.mjs`는 로컬 PNG를 격리 DB에만 읽습니다.
- 새 자료 추가: ① `decks/<과목>/<레벨>.json` 작성 ② `catalog.json`에 경로 등록 ③ `lib/sca-edu/decks.ts`에 import 등록. `tests/sca-edu.test.mjs`가 누락을 검사합니다.
- 디자인: 모든 슬라이드 흰 배경, 글자는 블랙·다크그레이·그레이. 색은 `lib/sca-edu/theme.js` 한 곳에서만 바꿉니다. PPTX는 발표 PC에 Pretendard 글꼴이 설치돼 있어야 화면과 같게 보입니다.
- 저작권 표시: 웹·발표 모드 워터마크와 웹/PPTX 모든 슬라이드 하단에 `© Inyub kim_Thecup Edu`를 표시합니다. 원본 이미지의 별도 저작권·출처는 유지합니다.
- 일반인용 설명을 보강한 Foundation v1.3: 물과 예방정비 95장, 지속가능성 93장입니다. 각 과목의 기존 이론과 가상 사례 6개(자료 관찰, 판단 질문, 해설)는 유지하고 일부 전문 표현을 쉬운 말로 고쳤습니다. 웹의 `정답 보기`로 먼저 생각한 뒤 해설을 확인하며, PPTX는 정답 공개 페이지를 포함해 각각 105장·103장입니다.
- 쉬운 용어 설명: 물 24장·지속가능성 19장의 짧은 설명을 관련 주제 바로 앞에 배치했습니다. 165개 항목마다 `수업 용어 / 쉬운 뜻 / 생활 속 예시`를 제공합니다. 카트리지·가스켓·플러싱·알칼리도·TDS, 이해관계자·프리미엄·원단위·%p 등을 다루며 본문 18pt 이상의 편집 가능한 표를 웹/발표/PPTX에서 공통 사용합니다. 수강생에게도 보이는 본문이고 발표자 노트에만 넣지 않았습니다. 생활 비유는 제조사 작업 지침이나 실제 측정값을 대신하지 않습니다.
- 물 사례: 같은 TDS의 다른 수질, 2 L 혼합 계산, 사용량 변화와 필터 교체, 그룹 누수 인계, 평균과 도징 편차, 필터 교체 후 유량 저하. 지속가능성 사례: 참여 기회, 가격·수확량과 농가 손익, 인증 프리미엄·비용, 반납률과 환경 주장, 총전력·원단위, 폐기율·폐기 무게. 실제 센터·직원·농가 자료나 업계 기준으로 제시하지 않습니다.
- `caseStudies`의 가상 계산 조건과 `caseId`·`caseStage`로 사례 흐름을 검사합니다. Foundation 레벨·review 상태·기존 열람 권한은 유지하고, 위험한 장비 작업은 제조사 절차와 교육받은 담당자 범위로 제한합니다.
- 보호: 우클릭·드래그·선택 제한, API `Cache-Control: private, no-store`. 인쇄는 승인된 과목·레벨의 출력 전용 화면으로 연결하며 화면 캡처나 이미 저장한 PDF를 원격으로 회수할 수는 없습니다.

### PDF 저장·인쇄

- 수강생·관리자는 교육자료의 **PDF 저장·인쇄**를 누릅니다. 현재 과목·레벨·언어로 `/education/print`가 새 탭에 열리고, 기존 인증 API에서 열람 권한을 다시 확인합니다. 수강생에게 원본 강사 PDF나 관리자 PPTX 다운로드 권한을 추가하지 않습니다.
- 전체·현재 슬라이드·직접 지정 범위(`1-5, 8`), A4 가로 1장씩 또는 A4 세로 2장씩을 선택합니다. **정답 함께 출력**은 기본 해제입니다. 인쇄 창에서 PDF 저장 또는 프린터를 선택합니다. 브라우저·기기에 따라 인쇄 대화상자의 메뉴 이름은 다를 수 있습니다.
- 기존 슬라이드 좌표·Pretendard·차트·필수 원본 이미지·저작권 표시를 유지합니다. 발표자 노트·내부 메모는 출력하지 않습니다. 이미지·글꼴 준비 실패 또는 잘못된 페이지 범위는 출력 버튼을 비활성화합니다. 미리보기는 한 장씩 넘기되 인쇄에는 선택한 전체 페이지가 포함됩니다.
- 서버에 PDF 파일을 생성·공개 저장하지 않고 브라우저에서 출력합니다. 출력 페이지는 `private, no-store`·`noindex, nofollow`이며 기존 개인별 과목·레벨 승인 상태, 자료 검토 상태, 운영 DB를 변경하지 않습니다.
- 검수: `tests/sca-print.test.mjs`, localhost 메모리 DB `qa/sca-print-check.mjs`, 생성 PDF의 페이지 수·A4 방향·한글 텍스트·이미지·저작권 검수 및 Poppler 렌더링 `qa/inspect-edu-pdf.py`. QA 산출물은 공개 파일이 아닌 `outputs/qa/sca-print`에만 둡니다.

- CSV: 학생 이름과 연락처는 이관하지 않고 월별 총매출·순익·비개인 메모만 이관

## 환경 변수

`.env.example`을 참고해 로컬 환경에 아래 값을 설정합니다.

- `SESSION_SECRET`: 24자 이상의 무작위 세션/휴대폰 해시 비밀키
- `BOOTSTRAP_CODE`: 최초 관리자 1명 등록에만 사용하는 일회성 코드
- `OPERATOR_INITIAL_SECURITY_CODE`, `STUDENT_INITIAL_SECURITY_CODE`: 첫 로그인 보안 설정에만 쓰는 숫자 4~32자리 초기 코드. 운영 값을 소스에 기록하지 않습니다.

운영 값은 소스나 `.openai/hosting.json`에 넣지 않고 호스팅 환경 변수로 설정합니다.

로그인 보안코드는 서버 비밀키로 보호된 해시만 D1에 저장합니다. 관리자는 `직원 · 권한 → 보안코드 설정`에서 현재 운영자 코드를 확인한 후 각 대상의 코드를 변경할 수 있습니다. 변경 후에는 해당 대상의 기존 로그인 세션이 즉시 무효화됩니다. 초기 코드는 설정이 없는 경우에만 적용되며, 코드 변경 후 초기 값으로 되돌아가지 않습니다. 공통 코드는 휴대폰 소유 인증이나 MFA를 대신하지 않습니다.

## 가장 쉬운 배포 방법

운영 Worker는 루트의 `wrangler.jsonc`로 배포합니다. GitHub 자동 배포를 사용하려면 아래와 같이 Cloudflare Workers Builds 연결을 설정합니다.

1. 검증된 소스를 GitHub `main`에 푸시합니다.
2. Cloudflare Worker의 `Settings` → `Builds`에서 아래 값을 사용합니다.
   - Build command: `npm run build`
   - Deploy command: `npm run deploy:cloudflare`
   - Root directory: `/`
   - Production branch: `main`
3. 루트의 `wrangler.jsonc`가 vinext의 `dist/server`와 `dist/client` 결과물을 배포합니다.
4. D1 `DB`와 정적 파일 `ASSETS` 바인딩이 연결된 뒤 운영 주소를 검증합니다.

직접 확인할 때는 아래 명령이 모두 성공해야 합니다.

```bash
npm ci
npx tsc --noEmit
npm run lint
npm test
```

`SESSION_SECRET`은 휴대폰 번호 해시와 로그인 세션에 사용되므로 운영 중 임의로 바꾸지 않습니다.
바꾸면 기존 직원의 휴대폰 해시와 더 이상 일치하지 않아 로그인이 불가능해질 수 있습니다.

## GitHub·Cloudflare 이름 변경 순서

기존 운영 주소를 먼저 지우거나 끄지 말고 아래 순서대로 진행합니다.

### 0. 변경 전 기록

1. Cloudflare의 기존 Worker 이름, D1 바인딩, 환경 변수 목록을 기록합니다.
2. `SESSION_SECRET` 값은 변경하지 않습니다.
3. 새 배포 확인이 끝날 때까지 기존 `thecup-inventory` 주소를 유지합니다.

### 1. GitHub에서 할 작업

1. 기존 저장소에서 `Settings` → `General`로 이동합니다.
2. `Repository name`을 `thecup-edu-system`으로 바꾸고 `Rename`을 누릅니다.
3. 로컬 폴더의 GitHub 원격 주소를 확인합니다.

```bash
git remote -v
```

4. `origin`이 이미 있다면 새 주소로 변경합니다.

```bash
git remote set-url origin https://github.com/계정명/thecup-edu-system.git
```

5. `origin`이 없다면 새로 연결합니다.

```bash
git remote add origin https://github.com/계정명/thecup-edu-system.git
```

6. 검증된 `main` 브랜치를 올리고 GitHub Actions가 있다면 성공 여부를 확인합니다.

```bash
git push -u origin main
```

GitHub는 이전 저장소 주소를 새 주소로 전달하지만, Cloudflare의 Git 연동과 로컬 원격 주소는 새 저장소 이름으로 다시 확인합니다.

### 2. Cloudflare에서 할 작업

`thecup-inventory.<계정>.workers.dev`와 이 저장소의 Sites 배포 주소는 서로 다른 서비스입니다.

1. Cloudflare `Workers & Pages`에서 기존 `thecup-inventory` Worker를 엽니다.
2. `Settings`에서 Worker 이름을 `thecup-edu-system`으로 변경합니다.
3. 연결된 저장소가 `dlsduqdl1227-spec/thecup-edu-system`, 운영 브랜치가 `main`인지 확인합니다.
4. Build command를 `npm run build`, Deploy command를 `npm run deploy:cloudflare`로 설정합니다.
5. 루트의 `wrangler.jsonc`에서 Worker 이름이 `thecup-edu-system`인지 확인합니다.
6. D1 바인딩은 `DB`, 정적 파일 바인딩은 `ASSETS`인지 확인합니다. R2는 사용하지 않습니다.
7. 런타임 Secret으로 `SESSION_SECRET`과 `BOOTSTRAP_CODE`를 등록한 뒤 새 버전을 배포합니다.
8. 새 주소에서 로그인, 직원별 권한, 매출, 재고, 영수증, 교육자료 화면을 차례로 확인합니다.
9. 기존 주소를 사용하던 직원이 있다면 이전 주소에서 새 주소로 전달하는 리디렉션을 별도로 유지합니다.

운영용 서비스는 `workers.dev`보다 소유한 맞춤 도메인 연결을 권장합니다. 새 주소 검증이 끝나기 전에는 기존 Worker나 D1 데이터를 삭제하지 않습니다.

## 상담 접수 알림과 상담 DB 관리

- 관리자·담당 강사가 로그인한 사이트를 보고 있을 때 30초마다 새 상담을 확인합니다. 상단 알림에서 상담 접수함으로 이동합니다. 창으로 돌아오면 다시 확인합니다. 사이트를 닫아도 받는 OS 푸시는 아래 기기별 알림 설정을 사용합니다. 문자·카카오톡 발송은 하지 않습니다.

- 상담·수업 관리에서 **상담 접수 / 수강생 / 미승인 회원 / 수업 승인·완료**를 분리합니다. 수강생 탭은 예약 권한이 승인된 계정만 표시합니다. 별도 수강생 목록도 승인 계정을 기본으로 표시합니다.
- 상담 접수함은 성함·연락처 끝 4자리 검색, 상담 상태 필터, 최근/오래된 접수순·이름순·최근 수정순 정렬, 25건 페이지 이동을 지원합니다. 알림은 삭제되지 않은 `NEW` 상담 건수이며 상세를 열었다고 자동으로 처리되지는 않습니다.

## FLOW 일정 표시와 개인정보 분리 (2026-11-19)

- 일반·수강생 캘린더에 FLOW와 겹치는 예약 회차만 ‘예약 있음’으로 표시합니다. 같은 날의 나머지 회차는 예약 가능합니다. 공개 API의 `busyDays`는 날짜/고정 문구, `busySlots`는 기존 예약 회차 시간/고정 문구만 반환합니다. FLOW 일정 ID·개수·제목·실제 정밀 시간·장소·메모는 전달하지 않습니다.
- 관리자 상담·수업 관리의 FLOW 달력에서는 월·날짜를 선택해 실제 일정명·시간·장소를 확인합니다. 일반 직원·시간강사·수강생·비로그인은 상세 API를 사용할 수 없습니다. 공개 URL에 `details=1` 등을 붙여도 상세 내용이 반환되지 않습니다.
- 서버 비밀 인증의 FLOW 피드는 version 2의 익명 시간 구간을 제공하며 `?details=1&month=YYYY-MM`에서만 상세를 반환합니다. EDU는 관리자 권한을 확인한 뒤 상세를 서버에서 조회합니다. 상세 내용은 DB나 오프라인 캐시에 저장하지 않으며 개인 메모·참석자·직원 데이터는 가져오지 않습니다.
- 기존 센터/수동 차단 일정 범위는 유지하되 시간 지정 일정은 `[시작, 종료)`와 겹치는 수업 회차만 막습니다. 종일 일정만 날짜 전체를 막고 ‘종료 미정’ 표시가 있어도 저장된 시작/종료를 사용합니다. 실제 종료 시간이 없으면 차단을 보류하고 관리자에게 알립니다. 기존 예약/수동 휴강을 수정하지 않고 구형 날짜 전용 예약 가드를 시간대 가드로 교체합니다.
- 이동·수정·삭제는 즉시 연동/30초 화면 갱신/예약 직전 재확인에 반영됩니다. 상세 연결이 실패해도 마지막 정상 차단 구간을 유지하고 원본 재확인 실패 시 신규 예약/확정은 503으로 안전하게 중단합니다.
- 검수: `tests/calendar-sync.test.mjs`, `tests/flow-calendar-view.test.mjs`, `qa/flow-calendar-view-check.mjs`. 양쪽 localhost 메모리 DB로 관리자·일반·수강생 표시와 수정/삭제 연동을 검사하며 운영 기록을 테스트용으로 변경하지 않습니다.
